核心功能

左右双窗口、各自多标签，本地与远程随时同屏

IDE 式双窗格，左右各自多标签

  • 左右两个文件夹窗口各自独立多开标签页，每个标签既可浏览本地、也可连接远程主机，任意组合同屏
  • 四方向传输全覆盖：本地⇄本地、远程⇄远程，支持多选与目录递归
  • 按住条目拖到对侧即传，悬停高亮提示目标目录
  • 同步浏览、文件比对高亮、橡皮筋框选多选

服务端命令通道：能不过本机，就不过本机

  • 远程 → 远程同机直达：服务器本地 cp 直拷，文件数据只在服务器磁盘间流动，零本地流量——传统客户端要先把整个目录下载回来再传上去
  • 海量文件秒删：服务端一条 rm -rf，告别 SFTP 协议逐条遍历删除的漫长等待
  • 命令不可用时（如服务器禁用 shell）自动回退 SFTP 逐条方案，最坏情况也和传统客户端持平，永远不会更差

大文件校验秒算，连接稳定可查

  • 文件校验码：SHA-256 / SHA-512 / SM3（国密）下拉即算 + 一键复制
  • 服务端命令优先：数百 MB 大文件校验秒级完成，不占传输链路；命令缺失自动拉流回退
  • 主动心跳保活：连接闲置不断线，保活间隔可调——FileZilla 没有主动保活，挂机久了就掉线
  • 首次连接确认主机指纹（SHA256），服务器密钥变更直接拒绝，防中间人攻击；密码 / 私钥认证，超时与重试全可调

为什么 FileZilla / WinSCP 不做命令通道？

它们面向任意服务器：大量主机用 OpenSSH 的 ForceCommand internal-sftp 把用户锁死在 SFTP 子系统里，shell 根本不存在；而 SFTP v3 协议本身没有递归删除、服务端复制原语，所有人只能逐条往返。FileZilla 更是连 SCP 都不支持，官方论坛多次拒绝"执行命令"的特性请求——协议里没有的一概不做，换来的是处处可预测。

命令通道优先，SFTP 兜底：能快则快，绝不更慢

命令通道可用时，服务端直达快至百倍；不可用时自动回退 SFTP 逐条方案，最坏情况就是 FileZilla 的现状——永远不会更差。WinSCP 的 SCP 模式其实试过命令路线，因兼容负担太重已沦为遗留模式；iFreeSftp 的混合分流让它只赚不赔。
